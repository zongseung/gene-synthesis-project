## 2. 현재 GeneDiffusion 파이프라인 vs 제안 아키텍처

### 현재 GeneDiffusion (UNet 기반)

```
VCF (염색체별) -> 유전자 어노테이션 (refGene hg19)
              -> MAF > 0.01 필터, biallelic SNP만
              -> 유전자 수준 PCA (8개 주성분)
              -> 토큰화 (gene_count x 8)
              -> 제로 패딩 → 26624
              -> 입력 텐서: (batch, 8, 26624)
              -> 1D UNet Diffusion (코사인 스케줄, 500 타임스텝)
              -> 조건부 입력: one-hot 클래스 레이블 (26 클래스), 업샘플링 블록에서 곱셈 주입
              -> 손실 함수: MSE (노이즈 예측만)
```

### 제안 아키텍처 (FiLM + DiT)

```
SNP/하플로타입 벡터 (고정 길이 1D, 예: 10K SNP 위치)
  -> 1D CNN Stem (근거리 LD, 하플로타입 청크 추출)
  -> 토큰/잠재 공간 프로젝션 + 위치 임베딩
  -> 조건부 DiT 백본 (블록별 FiLM 변조: h' = gamma * h + beta)
  -> Diffusion 디노이징 헤드
  -> 분포 매칭 손실 (L_sfs + L_ld + L_hap)
  -> 전체 손실 = L_diffusion + L_dist
```

## 3. 적용 가능성 분석

### 3.1 적용 가능한 구성 요소

#### FiLM Conditioning (gamma, beta 변조)

- 현재 코드에서 이미 유사한 패턴 사용 중: `UpsamplingBlock`에서 `x * c_emb + t_emb`
- FiLM은 이 접근법의 체계적 확장
- 26개 인구군 + 5개 슈퍼 인구군 계층 구조 활용 가능
- **코드 변경 최소로 직접 적용 가능**

#### 1D CNN Stem

- 입력 형태 (batch, 8, 26624)가 1D 컨볼루션과 호환
- 근거리 SNP 패턴을 효과적으로 포착 가능
- 주의: 현재 데이터는 이미 PCA로 압축된 상태이므로 원시 LD 정보가 상당 부분 손실됨

#### DiT 백본

- 장거리 유전자 간 상호작용 포착에 이론적으로 우수
- 현재 UNet은 국소 수용 영역(receptive field)에만 의존

---

### 3.2 핵심 문제점

#### 문제 1: 샘플 수 대비 모델 복잡도

- **2,504명**은 DiT급 Transformer를 학습시키기에 극히 적은 수
- 현재 UNet도 100 에포크로 겨우 수렴하는 상황이며, DiT는 파라미터 수가 수배~수십배 증가
- FiLM 파라미터 생성기까지 추가하면 용량이 더 커짐
- **오버피팅 위험이 매우 높음**

#### 문제 2: 분포 매칭 손실(Distribution Matching Loss)의 전제 조건

| 손실 구성 요소 | 필요 데이터 | 현재 파이프라인 상태 |
|---------------|-----------|-------------------|
| SFS (사이트 빈도 스펙트럼) | SNP별 대립유전자 빈도 | Gene PCA 이후 **소실됨** — 개별 SNP의 AF 정보가 주성분에 흡수됨 |
| LD 매칭 (쌍별 r^2) | 원시 유전형 또는 대립유전자 수준 데이터 | PCA 공간에서는 **무의미** — LD 구조가 주성분으로 축소됨 |
| 하플로타입 다양성 | 페이즈된 하플로타입 데이터 | Phase 3 데이터가 페이즈되어 있으므로 **가능**, 단 파이프라인 재설계 필요 |

#### 문제 3: 입력 표현의 불일치

- `architecture.md`의 가정: "SNP / Haplotype Vector x, 고정 길이 1D 시퀀스, 예: 10K SNP 위치"
- 현재 데이터 흐름: 수백만 변이 -> Gene PCA -> (2504 x ~21819 x 8) 텐서
- 이 둘은 **근본적으로 다른 표현 방식**
- 아키텍처는 **원시 SNP 수준 입력**을 상정하고, 현재 파이프라인은 **유전자 수준 잠재 공간**에서 동작

#### 문제 4: 연산 실현 가능성

- 전체 상염색체 VCF에는 **수천만 개**의 변이가 존재
- MAF > 0.01 필터 후에도 수백만~천만 수준 잔존
- DiT 어텐션은 시퀀스 길이에 대해 O(n^2): 원시 SNP 입력으로는 **비현실적**
- Gene PCA 압축을 사용하면 차원은 줄지만, 아키텍처의 핵심 장점(SFS, LD, Haplotype 손실)을 활용할 수 없음

## 4. 실현 가능한 구현 전략

| 전략 | 설명 | 실현 가능성 | 작업량 |
|------|------|-----------|--------|
| **A. FiLM만 도입** | 현재 UNet 유지, 조건부 메커니즘만 FiLM으로 교체. 계층적 인구군 임베딩 (pop -> superpop) 추가. | **높음** | 낮음 |
| **B. 하이브리드: UNet + 분포 손실** | 원시 SNP 표현을 보존하도록 전처리 재설계. 유전자 윈도우 기반 LD/SFS 보조 손실 추가. | **중간** | 중~높음 |
| **C. 전체 아키텍처 전환** | CNN Stem -> DiT -> Distribution Loss 엔드투엔드 구현. | **낮음** | 높음 |

### 전략 A: FiLM만 도입 (권장 첫 단계)

```python
# FiLM을 기존 UNet에 통합하는 의사 코드
class FiLMGenerator(nn.Module):
    def __init__(self, cond_dim, hidden_dim, n_blocks):
        # 인구군 임베딩 (26 클래스) + 슈퍼 인구군 임베딩 (5 클래스)
        # 타임스텝 임베딩
        # MLP -> 블록별 (gamma, beta) 쌍 생성

class UNetBlockWithFiLM(nn.Module):
    def forward(self, x, gamma, beta):
        h = self.base_forward(x)
        return gamma * h + beta  # FiLM 변조
```

- 파이프라인 변경 최소화
- 오버피팅 위험 증가 없음
- 추가 투자 전에 FiLM 효과를 검증할 수 있음

### 전략 B: 하이브리드 (중기)

- `preprocess_1kg.py`를 재설계하여 Gene PCA 대신 윈도우 기반 원시 유전형 출력
- 로컬 윈도우 단위(예: 1000-SNP 슬라이딩 윈도우)로 LD/SFS 손실 정의
- UNet 또는 경량 Transformer 백본 유지
- 가변 길이 유전자 영역 처리에 주의 필요

### 전략 C: 전체 DiT 전환 (장기, 조건부)

시도 전 선행 조건:
1. 데이터 증강 전략 (하플로타입 셔플링, 염색체 단위 학습, 합성 오버샘플링)
2. 효율적 어텐션 메커니즘 (선형 어텐션, Flash Attention, 윈도우 어텐션)
3. 계층적 토큰화로 실효 시퀀스 길이 축소
4. 전략 A/B가 불충분하다는 검증 결과

## 5. 결론

제안 아키텍처는 유전형 생성 모델로서 이론적으로 우수하지만, 현재 데이터 및 파이프라인과 **3가지 근본적 불일치**가 존재한다:

1. **Gene PCA 표현 vs 원시 SNP 입력 가정**: 분포 매칭 손실(SFS, LD, Haplotype)은 PCA 공간에서 정의할 수 없음
2. **2,504 샘플 vs DiT 용량**: Transformer 기반 모델은 데이터 효율이 낮아 심각한 오버피팅 우려
3. **수천만 변이 vs 시퀀스 길이**: 원시 SNP 입력 시 DiT의 O(n^2) 어텐션이 연산적으로 비현실적

**권장 사항**: 단계적 접근 채택
1. **1단계**: 기존 UNet에 FiLM 조건부 메커니즘 통합 (전략 A)
2. **2단계**: 원시 유전형 표현을 위한 전처리 재설계 및 분포 손실 추가 (전략 B)
3. **3단계**: 데이터 증강 및 효율적 어텐션이 갖춰진 후에만 전체 DiT 전환 평가 (전략 C)
